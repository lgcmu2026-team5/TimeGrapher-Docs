## 🔴 긴급 — Milestone 2 제출 전 (~ 6/22)

### 1. 6/18 수업 — 아키텍처 뷰 템플릿 확인 및 적용
수업에서 제공하는 템플릿을 확인한 뒤 즉시 팀 문서에 반영한다. 모든 뷰가 동일한 형식을 따르도록 통일해야 한다.

- **담당:** Speaker 1, Speaker 4, Speaker 5
- **기한:** 6/18

### 2. 모듈 사용 뷰 — 구체적 uses 관계로 재작성
레이어드 뷰와 중복되지 않도록 실제 디렉터리·클래스·파일 단위의 구체적 의존성을 표시한다. 레이어와 다른 기호를 사용하고, 차이가 불명확하면 두 뷰를 결합한다.

- **담당:** Speaker 1

### 3. MVC 뷰 완성 — 프로젝트 설계 중심으로 정리
일반 MVC 설명은 외부 링크로 대체한다. 세부 MVC 다이어그램을 완성하고, 컨트롤러 요소를 상하 배치로 변경해 가독성을 높인다. 모듈 사용 뷰에 색상으로 MVC 역할 표시도 검토한다.

- **담당:** Speaker 1, Speaker 4

### 4. 배포 뷰 신규 작성
Raspberry Pi·모니터·마이크 등 하드웨어 인프라와 연결 방식(Wi-Fi, USB 등)을 보여주는 시각적인 배포 뷰를 만든다. 파일 시스템 구조가 아니라 물리적 장치 중심으로 작성한다.

- **담당:** Speaker 1, Speaker 4

### 5. 문서 구조 정리 — approaches → views rename
"architectural approaches"를 "architectural views"로 변경한다. 패턴·스타일 정보는 관련 뷰 내부에 포함하고, Milestone 1 문서를 별도 보존하지 않고 기존 문서를 갱신하며 Git 이력으로 관리한다.

- **담당:** Speaker 1, Speaker 4

### 6. CPU 사용량 표기 수정
0~400 스케일에서 % 기호를 사용하면 0~100으로 오해된다. % 제거 또는 스케일 명시로 수정한다.

- **담당:** Speaker 4

## 🟠 높음 — 이번 주 내 처리 (고객 응답 대기 필요)

- **담당:** Speaker 4

### 8. 그래프/포지션 명칭 불일치 — 고객 확인
프로젝트 문서와 reference implementation 간 명칭 차이를 설명하고, 문서 기준 구현이 맞는지 확인받는다. 위 이메일에 함께 포함하면 효율적이다.

- **담당:** Speaker 1, Speaker 4

### 9. Zoom 기능 범위 — 고객 확인
rate and scale graph만인지 다른 그래프에도 필요한지 확인한다. 이미 구현됐거나 쉬운 부분은 차별화 요소로 별도 질문 없이 적용 검토. x/y축 stretch까지 필요한지도 확인.

- **담당:** Speaker 1, Speaker 4

### 10. 터치 입력 요구사항 — 고객 확인 + Piazza
touch screen이 single touch만 지원하고 multi-touch 불가하다는 점을 설명한 뒤, mouse·keyboard 입력으로 충분한지 확인. Piazza에도 올려 다른 팀 기존 답변 확인.

- **담당:** Speaker 1, Speaker 5
