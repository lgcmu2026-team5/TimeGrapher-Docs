# ADR004 - Separation of App, test, and verify modules to support AI utilization, TDD, and team collaboration

The TimeGrapher system requires a high level of modifiability and extensibility to efficiently add new measurement metrics and graph analysis modes. Currently, our team consists of 6 members working simultaneously on a single codebase. Thus, a structure that minimizes merge conflicts and supports parallel development is essential. Furthermore, as we actively utilize on-device AI and AI coding assistants, thorough human review supported by a Test-Driven Development (TDD) environment is critical to automatically verify behaviors. We also need a way to share architectural decisions across the entire team to reduce communication overhead.

## Decision
*   **We will separate the fundamental project structure into independent `App`, `test`, and `verify` modules.**
*   **We will adopt Test-Driven Development (TDD) practices to ensure that the core domain logic remains highly testable and UI-agnostic.**
*   **We will enforce automated testing via the `test` and `verify` modules as a mandatory step before any code commit, providing a verified baseline to assist human review of AI-assisted code.**

## Rationale
*   **Collaboration Efficiency:** By physically separating the core logic, UI, and test environments into distinct modules, our 6-person team can work independently and in parallel, drastically reducing merge conflicts.
*   **Safety Net for AI Code:** AI-suggested code may contain unexpected errors. By adopting TDD, pre-written tests act as a primary safety net. When our 6 members peer-review each other's code, they can merge changes more objectively and efficiently based on passing tests.
*   **Rejected Alternative:** We considered placing all source code within a single `App` module. However, this was rejected because the burden of manually reviewing and verifying the extensive code generated by AI would be far too high for the team members.

## Status
Accepted

## Consequences
**Positive**
*   Project development speed improves because basic test automation significantly reduces the burden of reviewing AI-generated code.
*   An automated testing foundation is established, ensuring that code written by teammates or AI can be merged into the main branch with high confidence.

**Negative**
*   Adhering to TDD principles and writing test code first may increase the initial learning curve and development time for all team members.
*   There is overhead in maintaining dependencies among the three modules, configuring the CI (Continuous Integration) pipeline for 6 developers' continuous inputs, and keeping the ADR documents current.
