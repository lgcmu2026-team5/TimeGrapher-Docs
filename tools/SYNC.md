# SYNC — Quire(ARCHI-265.json) ↔ Milestone 폴더 정합성 점검 지시문

> 이 파일은 Claude에게 주는 **지시문**이다. 사용자가 "SYNC.md 읽고 정리해줘"라고 하면
> 아래 절차를 그대로 수행하고, **불일치 항목을 표로 정리해서** 보여줄 것.

## 목적
`tools/ARCHI-265.json`(Quire에서 추출한 작업 트리)과 이 레포의 `Milestone{1,2,3}/` md 문서를 비교해,
**Quire를 직접 고쳐야 하는 불일치만 찾아 보고**한다. 최종 행동은 "Quire에서 수정"이다.

## 수정 기준 (정본 = 레포 md 문서)
- **레포의 Milestone 문서를 정본(source of truth)으로 보고, Quire(`ARCHI-265.json`)를 거기에 맞춘다.**
- 따라서 RESULT의 "비고·제안" 칸은 항상 **"Quire를 …로 변경/추가/삭제"** 형태로 적는다.
- **Quire 수정이 필요 없는 항목은 보고하지 않는다.** 다음은 표에서 제외:
  - 폴더가 비어 있거나 미착수라서 생긴 차이(예: Milestone2/3 산출물 미생성) — 비교할 정본 문서 자체가 없음.
  - 순수 문서 간 차이(초안 vs 공식 등 Quire와 무관).
  - 일치/이상 없음 항목.

## 수행 절차

### 1단계 — JSON을 Quire 기준으로 읽고 이해
- `tools/ARCHI-265.json`을 읽는다. 이것은 Quire 프로젝트(`ARCHI-265`)의 export다.
- 트리 구조: `tasks[]` → 각 task의 `tasks[]`(하위 작업) 재귀.
- 해석에 필요한 코드:
  - **state**: `0` = 미시작, `10` = 진행 중, `100` = 완료.
  - **assignees / followers / createdBy**: `users[]`의 `oid`로 매핑해 사람 이름으로 환산.
  - **due / start / createdAt**: epoch millis (UTC). 날짜로 환산.
  - task `description`에 GitHub/문서 링크가 있으면 어떤 산출물과 연결되는지 기록.
- 마일스톤별로 어떤 작업·실험(EXP-##)·산출물이 있고 각 상태가 무엇인지 목록화한다.

### 2단계 — 각 Milestone 폴더 실제 내용 파악
- `Milestone1/`, `Milestone2/`, `Milestone3/` 폴더의 실제 파일을 훑는다
  (문서 제목, 실험 ID/번호, 다루는 산출물, 작성 여부).
- 특히 실험 계획/리스크/아키텍처 문서에서 **EXP 번호·실험 제목·대응 리스크·QAS 매핑**을 추출한다.

### 3단계 — 불일치 탐지 (아래 유형을 점검)
1. **존재 불일치**: JSON에는 있는데 폴더에 산출물이 없음 / 폴더엔 있는데 JSON task엔 없음.
   - 예: JSON `Experiments/Results`에 EXP-01~05만 있고 EXP-06이 빠짐 등.
2. **번호·ID 불일치**: 같은 실험인데 JSON과 문서에서 EXP 번호가 다름 (예: EXP-A1 vs EXP-01).
3. **제목·명칭 불일치**: 같은 항목의 이름이 서로 다름.
4. **상태 불일치**: JSON state(완료/진행/미시작)와 폴더 실제 진행도가 어긋남
   (예: JSON은 완료인데 문서가 TO-DO/초안 상태, 또는 그 반대).
5. **매핑 불일치**: 대응 리스크(R-##)·QAS 매핑이 JSON 설명과 문서에서 다름.
6. **담당/일정 불일치**: 명백히 어긋나는 담당자·기한이 있으면 기록(부차적).

### 4단계 — 결과 저장 (표 필수)
- 발견한 불일치를 **다음 표 형식**으로 정리한다:

| # | 유형 | 항목 | JSON(Quire) 기준 | 폴더/문서 기준(정본) | 비고·제안 (Quire 수정) |
|---|------|------|------------------|----------------------|------------------------|

- **표에는 Quire를 수정해야 하는 불일치만 넣는다.** Quire 수정이 불필요한 항목(폴더 미생성/미착수, 초안 등 문서 내부 차이, 일치/이상 없음)은 올리지 않는다.
- 표 아래에 **한 줄 요약**(불일치 N건, 가장 시급한 1~2건)을 덧붙인다.
- 불일치가 없으면 "불일치 없음"이라고 명시한다.
- **결과는 이 폴더(`tools/`)의 `RESULT.md` 파일에 저장한다** (기존 내용은 덮어쓴다).
  - `RESULT.md` 맨 위에 점검 일시(사용자가 알려준 오늘 날짜)와 "SYNC.md 기준 자동 점검 결과"임을 한 줄로 명시한다.
  - 저장 후, 채팅에는 같은 표와 한 줄 요약을 함께 보여준다.
- **점검 대상 산출물 파일은 수정하지 않는다.** `RESULT.md` 작성과 아래 5단계(조건부 동기화)를 제외한 수정은 사용자가 따로 지시할 때만.

### 5단계 (조건부) — Quire → Project-Plan 문서 동기화
- **트리거: 4단계 결과 불일치 표가 0건(불일치 없음)일 때만 수행한다.** 불일치가 1건이라도 있으면 먼저 그것부터 Quire에서 해소하고, 이 단계는 건너뛴다.
- **대상 파일**: 레포 **최상위(root)의 `Project-Plan.md`** 한 개. 없으면 새로 생성한다.
- **동작**: **이 단계에 한해 Quire(`ARCHI-265.json`)를 기준(소스)으로** `Project-Plan.md`에 **전체 task 리스트와 완료 여부 등**을 Quire 상태에 맞춰 작성/갱신한다.
  - Milestone 1/2/3 → 하위 task 트리 구조를 그대로 반영한다.
  - state 표기 매핑: `0` = 미착수, `10` = 진행 중, `100` = 완료 (체크박스/상태 표기로 반영).
  - task의 추가/삭제/이름, 담당·기한 등도 Quire 기준으로 맞춘다.
  - 매번 Quire 기준으로 덮어쓰며, 맨 위에 동기화 일시를 한 줄로 적는다.
- 적용 전 변경 요약을 보여주고, 적용 후 **어떤 파일에서 무엇을 바꿨는지** 보고한다.
