# ADR 003: Concurrency Isolation for GUI Real-Time Performance and Core Analysis Protection

기계식 시계 오디오는 28800 BPH 기준 비트당 125 ms의 실시간 마감 예산을 가진다. 캡처·분석·렌더링이 단일 스레드 동기 체인이면, Avalonia 드로잉이나 OS 렌더 지연이 파이프라인 전체를 차단해 신호 누수와 화면 멈춤을 일으킨다. RPi5 리눅스의 GUI 가속 리스크까지 겹쳐 백엔드 루프 격리가 필요하다.

## Decision
SAP **동시성 도입(introduce concurrency) tactic**으로 데이터 코어와 GUI를 격리한다. 분석 엔진을 전용 고우선순위 스레드로 분리하고 UI는 렌더링만 담당한다. 스레드 간 전달은 단일 writer/reader 동기화 링버퍼(30초, Shared-Data)와 바운드 Producer-Consumer 큐로 분리한다.

## Rationale
* **마감 보장**: UI가 지연돼도 전용 스레드의 분석 엔진은 125 ms 주기를 침범당하지 않는다.
* **플랫폼 리스크 방어**: RPi5 주사율 저하 압력에서 코어 분석을 구조적으로 보호한다.

## Status
Accepted

## Consequences
* 공유 데이터의 레이스 컨디션·스레드 안전 계약 준수로 복잡성이 증가한다.
* 런타임의 스레드 우선순위 지정은 Linux/Pi5에서 무효이므로, 실제 보호는 우선순위가 아닌 바운드 큐 구조에 의존한다(ADR 005).
