# ADR 005: Zero-Allocation via Static Triple-Buffer Pool (Double Buffering) and Latest-Wins Scheduler

동시성 격리(ADR 003)와 Pipe-and-Filter(ADR 004)에 따라 스레드 경계로 대용량 프레임(수 MB)을 반복 전달한다. 비트 주기(125 ms)마다 이를 힙에 new/해제하면 LOH 오염·파편화로 GC 스파이크가 발생해 마감을 깬다.

## Decision
정상 상태 무할당을 위해 **고정 3버퍼 풀**(SAP 분류상 Double Buffering의 3버퍼 구현)과 **Latest-Wins 스케줄러**를 적용한다. 분석 스레드는 미리 확보한 3버퍼를 순환 복사하고, UI 측 렌더 스케줄러는 렌더 예산(33/100 ms)을 초과한 이전 프레임을 누적하지 않고 최신 버퍼로 병합·폐기한다. 캡처 진입부는 스택 할당 + 2세그먼트 블록카피로 힙 할당을 피한다.

## Rationale
* **GC churn 제로화**: 실시간 루프에서 가비지 생성을 배제해 GC 스파이크를 막는다.
* **UI 지연 차단**: Latest-Wins가 대기열을 최신 1프레임으로 유지해 UI 부하가 분석 스레드를 블로킹하지 않는다.

## Status
Accepted

## Consequences
* UI 주사율 초과 중간 프레임은 유실된다. 실시간 모니터링에선 '최신성'이 우선이므로 정당한 트레이드오프다.
* 3버퍼 상주로 기본 메모리 풋프린트가 소폭 증가한다.
