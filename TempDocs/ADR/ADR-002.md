# ADR 002: Adopt a Three-Layer Architecture (App / Platform / Core)

C#/.NET + Avalonia(ADR 001) 위에서, 분석 도메인·OS 입출력·GUI 책임이 섞이지 않게 분리해야 한다. 분석 로직이 UI·OS에 직접 의존하면 변경이 번지고 이식·테스트가 어려워진다.

## Decision
시스템을 **App / Platform.* / Core 3계층**으로 나누고 하향 단방향·비순환 의존만 허용한다.
* **Core** — 분석 도메인만 담당, 외부 OS 참조 0개.
* **Platform.*** — OS 오디오 스택을 Core 인터페이스(`ILiveAudioWorker`) 뒤에 은닉.
* **App** — Avalonia GUI·합성 루트, 구체 OS 분기는 `LiveAudioBackend` 한 곳. RID(`win-x64`/`win-arm64` · `linux-x64`/`linux-arm64`, 주 배포 타깃 `linux-arm64`)에 따라 Platform 참조를 조건부 바인딩.

## Rationale
* **변경용이성·이식성·시험용이성**: Core 무의존으로 알고리즘을 UI·OS와 분리해 영향 범위를 좁히고, GUI 없이 결정론적으로 테스트한다.

## Status
Accepted — `Core.csproj`/`TimeGrapher.App.csproj` 구현, SAP `Layers` ✓.

## Consequences
* 인터페이스·어댑터 보일러플레이트가 증가한다.
* 의존 방향은 문서만으로는 침식되므로 빌드 시점 강제가 필요하다(ADR 007).
* 동시성 격리(ADR 003)·Pipe-and-Filter(ADR 004)·라우팅(ADR 006)의 기반이 된다.
