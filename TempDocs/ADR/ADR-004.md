# ADR 004: Apply the Pipes and Filters Style to the Audio Processing Pipeline

데이터 흐름은 `캡처 → 검출 → 측정 → 시각화`의 단방향 선형이다. 이 로직이 GUI(Avalonia)나 OS 오디오 라이브러리에 강결합되면 알고리즘 변경이 표현 계층을 오염시키고, 신규 필터·그래프 추가와 OS 간 이식이 어려워진다.

## Decision
단계 분리의 기준으로 **Pipes and Filters 스타일**을 채택한다. 각 단계를 표준 인터페이스로 캡슐화하고, 검출→측정→시각화를 분석 스레드 내 단계형 데이터플로로 배선한다. 동시 파이프 경계는 `입력→링버퍼→분석`·`분석→녹음 큐` 두 곳에만 두고, 나머지 단계는 단일 스레드 동기 호출로 둔다.

## Rationale
* **변경용이성**: 의존성 차단으로 기존 코어 수정 없이 새 필터·뷰를 주입한다.
* **이식성**: 분석 알고리즘과 GUI를 분리해 CLI·벤치마크·타 OS로 이식한다.

## Status
Accepted

## Consequences
* 단계 경계마다 대용량 스냅샷(수 MB)이 전달돼 복사 비용이 든다 → 무할당 전술로 완화(ADR 005).
* 단계 분리·캡슐화는 충족하지만 완전한 비동기 파이프는 아니다 — 동시 경계가 두 곳에 그쳐 부분 적용에 머문다.
